Security

MarinOS applications are designed to be secure by default. Most MarinOS apps are hosted as static websites on GitHub Pages, which means they do not run server-side application code or maintain their own databases.

MarinOS provides common security standards and tools that each application uses. Every application also publishes its own security information so you can see how that specific app handles data and security.

GitHub Pages hosting

MarinOS applications hosted on GitHub Pages are static websites. This means:

  • Application files are delivered over HTTPS.
  • There is no MarinOS application server running behind the website.
  • GitHub Pages does not provide a MarinOS application database.
  • Browser-based applications can process files and information locally on your device without sending that information to MarinOS.
  • Passwords, API keys, private credentials, and other secrets must not be stored in published application code.
  • GitHub Pages does not allow applications to configure arbitrary HTTP response headers, so some browser security protections must be implemented within the application itself or are provided by the hosting platform.

If an application connects to an API or another external service, its Security page should describe that connection and what information may be sent.

How it works

MarinOS defines the common security standard. Each application keeps its own security.json file describing its security characteristics. That information is used to generate and validate the application's public security information.

App status

MarinOS uses Alpha, Beta, and Live to show the maturity of each app. Status helps people understand what to expect when using a MarinOS product.

Alpha

Alpha — Experimental and actively being developed.

Alpha apps are early versions used to explore ideas and test how something might work. Features may be incomplete or change significantly.

  • Frequent changes
  • Limited testing
  • Incomplete functionality
  • Experimentation

Beta

Beta — Working and available for real-world testing.

Beta apps have working core functionality and are being tested with real users. Features and workflows may continue to change based on feedback.

  • Working core features
  • Real-world testing
  • Continued improvements
  • Occasional limitations

Live

Live — Available for ongoing use.

Live apps are established products available for their intended users. They have stable core functionality and continue to be maintained and improved.

  • Stable core functionality
  • Ongoing maintenance
  • Regular improvements
  • Dependable use for the intended purpose
